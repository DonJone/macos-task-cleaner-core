## 帖子正文

各位 V 友 / 同行好：

平时编码做项目，经常不知不觉打开几十个应用程序。等到机器发热或准备集中精力时，想要把前台非必要的应用通通退掉，传统方式痛点非常明显：
1. 手动依次关闭：只要有一个软件有未保存改动，必然弹出模态对话框拦截，批量关闭流程直接卡住；
2. 命令行批量杀：如果写简单的 `killall` 脚本，不仅容易把自己正在跑的终端（如 iTerm2、Ghostty、Alacritty）一锅端，而且杀 Finder 会触发系统的 crash 监控，立刻被 `launchd` 重启复活；
3. 第三方商业工具：不少工具动辄几十兆常驻内存，要么基于 Electron 打包，要么闭源收费。

为此，我开发并开源了 **Task Cleaner for macOS**，今日正式发布 **v1.0.0** 正式版。这里向大家汇报一下核心设计与实现思路，欢迎大家体验与交流。

### 一、系统架构与技术选型

项目整体解耦为三层架构：

```text
[用户交互层]
  ├── GUI 客户端 (TaskCleaner.app): 基于 Swift 5.9 + SwiftUI MenuBarExtra 原生构建
  └── CLI 工具 (mtc): 纯键盘交互控制台，支持 --json 输出供脚本调度
       │
       ▼ (本地通信与调用)
[核心引擎层]
  └── macos-task-cleaner-core: Rust 语言实现，提供 AppKit 原生绑定与 POSIX 信号生命周期调度
```

* **UI 层为什么坚持原生 SwiftUI？**
  状态栏小工具的核心指标是低开销。采用原生构建，零 Electron 运行时负担，支持深浅外观自动切换，并原生内嵌 24 种常用语言。
* **核心层为什么用 Rust？**
  进程扫描与信号分发需要毫秒级的响应与严格的内存安全性，配合 `objc2` 框架直接与 AppKit `NSWorkspace` 进行无缝底层互操作。

### 二、解决的几个典型工程难题

#### 1. 弹窗阻塞与分级降级算法 (Tiered Termination)
传统信号往往要么是单纯的 `SIGTERM`（应用不响应时无能为力），要么是直接 `SIGKILL`（可能导致应用状态破坏）。
我们在 Rust 引擎中实现了标准的三段式平滑生命周期：
* 首先对目标发送 `SIGTERM`，触发常规下线逻辑；
* 启动高精度定时轮询（默认提供 400ms 宽限期时间窗），以较小开销检测 PID 是否存活；
* 一旦检测到超时仍存活（意味着被未保存弹窗等事件循环卡住），自动升级下发 `SIGKILL` 兜底，彻底终结前台卡顿。

#### 2. Finder 退出与 launchd 守护进程冲突
在 macOS 下向 Finder 发送 POSIX 信号，系统底层守护进程 `launchd` 会依据内置机制判定为非自愿崩溃，立刻以极高优先级将其拉起，产生“闪退并瞬间弹回”的反复自启问题。
我们在引擎中针对 `com.apple.finder` 单独走原生 AppKit 退出通道：
通过 `NSRunningApplication.terminate()` 显式向系统发出退出广播，告知系统属于用户主动发起，从而使 Finder 真正平稳退出，彻底避免自启循环。

#### 3. 四级白名单防御矩阵 (防止误杀终端与工作流)
很多开发者不敢用批量清理工具，最怕的就是脚本把当前工作环境退掉。我们设计了四层过滤：
* **L1 Core OS**：保护 Dock, WindowServer, SystemUIServer, loginwindow 等核心中枢；
* **L2 Context Shell**：递归解析调用者进程树，自动豁免调用者 PID、父进程 PPID，并硬编码保护 Terminal、Ghostty、iTerm2、Alacritty、VS Code 等主流开发环境；
* **L3 Persistent Utilities**：智能识别 Raycast、Alfred、Rectangle、输入法与监控小组件；
* **L4 User Config**：用户自定义规则，支持在 GUI 状态栏单键点击加盾牌，或在 `~/.config/mtc/config.toml` 中按 Bundle ID 自由配置。
